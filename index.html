One competition per calendar year (UTC). Every strategy is a username with one specific rule. Objective: highest return — risk management is deliberately not a criterion. Every fill consumes a captured official Kalshi order book (depth-bounded, limit-bounded, real fees and slippage); every settlement uses the official result. Nothing here submits orders to Kalshi — this is a paper desk, and every number traces to a committed, SHA-256-bound evidence file.

How a fill is verified

1 · Captured book

Each desk cycle commits verbatim GET /markets/{ticker} and GET /markets/{ticker}/orderbook responses with URL, timestamp and SHA-256 under data/season-2026/forward/cycle-*/evidence/.

2 · Depth-bounded fill

A paper order walks the captured ladder level by level, stops at its limit price, and pays the exact Kalshi quadratic taker fee 0.07·C·P·(1−P). Unfilled depth is logged, never invented.

3 · Official settlement

Positions close only at the market's official result field ($1/$0, no settlement fee). Slippage is (vwap − touch)·contracts versus the captured touch. The verification gate re-derives every one of these rows (V4–V9).

Simulated trade placementLive desk — open Kalshi event contracts

This section exists to simulate placing real trades on open Kalshi event contracts. It reads live, official prices straight from the public API in your browser (unauthenticated GETs — the same calls the collector uses) and lets you simulate a depth-bounded fill against the live captured order book with real fees and slippage. If your browser cannot reach the API (network/CORS), the desk falls back to the latest committed snapshot and labels it as such — it never invents a price.
